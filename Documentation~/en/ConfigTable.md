# ConfigTable Module

> Luban configuration table bridge layer: the framework defines interfaces and a singleton entry point, while the specific configuration code is generated by Luban from Excel into the project assembly.

`ConfigTable` module on the Runtime side only contains the `IConfigTableModule` interface and the `ConfigMgr` singleton: the former defines the three capabilities the framework cares about (multilingual text, sprite loading, UI window paths), and the latter serves as a global access point holding the implementation. The actual `ConfigTableModule` implementation, `Tables` collection, and individual table structures are all generated by the Luban export tool from templates into the project's `GameProto` assembly, and are automatically registered to `ConfigMgr.Instance.ConfigTableModule` via `RuntimeInitializeOnLoadMethod`. The accompanying editor tools (`Tools/Settings/ConfigTableSettings` and `Tools/Config` menu) handle the generation, relocation, and table export of the configuration table project directory.

## Core Features

- Framework and config table decoupling: The framework only depends on the `IConfigTableModule` interface; Luban-generated code lands in the business assembly, removing the config table does not affect compilation of other framework modules
- Lazy loading `Tables`: `Tables` is loaded only on first access to `ConfigTableModule.Tables`, automatically selecting binary (`ByteBuf`) or JSON (`JSONNode`) format based on the Loader return type in the generated code
- Editor-friendly: In non-play mode, `TextAsset` configuration is loaded directly via `AssetDatabase`, no need to start the resource system
- Multilingual bridging: Reads `LocalizedBean` fields from the generated code via reflection to register available languages, and expands `TbLocalizedStrings` into a `Dictionary<string, List<string>>` for use by the [Localization](Localization.md) module
- Sprite and UI configuration reading: `TbSprite` / `TbSpriteAtlas` / `TbUIWindow` tables drive sprite loading and window resource location
- Editor workflow: One-click copy of built-in Config template (including Luban executable, sample tables, generation templates), table export script invocation, and export path synchronization

## Core Types

| Class/Interface | Description |
|----------------|-------------|
| `Moirai.Atropos.ConfigTable.IConfigTableModule` | Config table helper interface: `GetAllLocalizedStrings`, `LoadSpriteByID`, `GetUIWindowLocation` |
| `Moirai.Atropos.ConfigTable.ConfigMgr` | `Singleton<ConfigMgr>` global entry point, holds a `ConfigTableModule` instance and forwards calls |
| `GameProto.Config.ConfigTableModule` | Luban-generated (templates `ConfigTableModule.cs` + `ConfigTableModule_Init.cs`), implements `IConfigTableModule`, includes lazy-loaded `Tables` and `Instance` singleton |
| `GameProto.Config.Tables` | Luban-generated table collection (e.g., `TbLocalizedStrings`, `TbUIWindow`, `TbSprite`, `TbSpriteAtlas` and business tables) |
| `Moirai.Atropos.ConfigTable.Editor.ConfigTableSettings` | Editor settings (`FrameworkSettings`): config table root directory, data/code export paths |
| `Moirai.Atropos.ConfigTable.Editor.LubanTools` | Table export menu: `Tools/Config/Luban Export Table &X`, `Tools/Config/Open Table Directory` |

## Quick Start

```csharp
// Business code: directly access the generated Tables (lazy-loaded, reads tables on first access)
Tables tables = ConfigTableModule.Instance.Tables;

// Read UI window configuration table (table example from built-in template)
if (tables.TbUIWindow.DataMap.TryGetValue("MainWindow", out var uiConfig))
{
    string prefabPath = uiConfig.DefaultRes;
}

// Framework-level API (forwarded via ConfigMgr singleton, no need to reference GameProto assembly)
// 1. Get all multilingual texts (called by Localization module on startup)
Dictionary<string, List<string>> localized = ConfigMgr.Instance.GetAllLocalizedStrings();

// 2. Load atlas sprite asynchronously by ID (TbSprite + TbSpriteAtlas cross-query)
Sprite icon = await ConfigMgr.Instance.LoadSpriteByID("icon_hero", cancellationToken: this.GetCancellationTokenOnDestroy());

// 3. Get UI window resource path
string location = ConfigMgr.Instance.GetUIWindowLocation("MainWindow");
```

## Configuration and Workflow

### Initial Generation

1. Open menu `Tools/Settings/ConfigTableSettings` (Config Table Settings)
2. Click "Generate Config to specified directory": copies the package's `Templates~/Config` (including `Excels` sample tables, `Luban` executable, `CustomTemplate` generation templates, `Defines`) to the selected directory; if the directory name does not contain "Config", a Config subdirectory is automatically created; if located within Assets, a `~` suffix is automatically appended to avoid Unity import
3. First-time use requires building the latest Luban with build-luban, or importing a pre-built Luban into the `[Luban]` folder of the config directory

### Daily Table Export

- Menu `Tools/Config/Luban Export Table` (menu item shortcut `Shift+X`) executes `gen_code_bin_to_project.bat` (`.sh` on OSX/Linux) in the config directory, generating data to `ClientDataOutPutPath` (default `Assets/AssetRaw/Default/Config/Table`) and code to `ClientCodeOutPutPath` (default `Assets/Scripts/GameProto`)
- Menu `Tools/Config/Open Table Directory` directly opens the config project
- After moving the config table directory, use "Redirect Config Directory" in the settings interface to re-specify it; after modifying export paths, click "Update Config Path" to automatically synchronize the keys in `path_export.conf` and the `CONFIG_PATH` constant in `CustomTemplate/ConfigTableModule_Init.cs`

### Generated Outputs

| Output | Description |
|--------|-------------|
| Table code under `Gen/` | Individual table Beans and `Tables` collection |
| `ConfigTableModule.cs` | Interface implementation: registration, multilingual parsing, Sprite/UI querying |
| `ConfigTableModule_Init.cs` | Loader: lazy-loads `Tables`, bridges YooAsset resource system |
| `ExternalTypeUtil.cs` | Luban extension type utility |

## Notes

- `ConfigTableModule` and `ConfigTableModule_Init` are both generated code from table export; manual modifications will be overwritten on the next export. Custom logic should be written on the business side or by modifying the `CustomTemplate` templates
- Configuration data is packaged according to the PRELOAD preload tag. At runtime, `LoadTextAsset` calls `GameModule.Resource.LoadAsset<TextAsset>` synchronously; ensure the resource system is ready
- When Config has not been generated, `ConfigMgr.Instance.GetAllLocalizedStrings()` returns `null` and reports "Generate Config first!"; the [Localization](Localization.md) module will fail to load as a result
- After modifying `m_ClientDataOutPutPath` / `m_ClientCodeOutPutPath`, you must manually execute "Update Config Path", otherwise `path_export.conf` still points to the old directory
- When the config root directory is located within Assets, a `~` suffix is automatically added (e.g., `Assets/Config~`); Unity will not import this directory, but the export script can still access it normally
