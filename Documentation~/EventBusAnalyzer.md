# EventBusAnalyzer：EventBus 使用规范分析器

`EventBusAnalyzer`（`SourceGenerators/EventBusAnalyzer.dll`，源码 `SourceGenerators/Source~/EventBusAnalyzer/`）随包自动生效：Unity 对引用 `Moirai.Atropos` 的所有程序集应用本分析器，无需任何工程配置。

> **只检查规范，不生成代码。** 本程序集是纯 `DiagnosticAnalyzer`，**不再包含 Source Generator**，不会产出任何 `SubscribeEvents()` / `UnsubscribeEvents()` 胶水代码。订阅与退订何时调用、怎么调用，全部由用户自行控制。

## 用途

静态检查 EventBus 使用规范，违规处以 MA 诊断告警（MA7xxx 段，统一 MA+4 位段号方案）：

1. 匿名函数不能用于订阅/退订（值等价匹配永不命中）；
2. 事件回调签名必须 `in` 修饰、参数类型与方法名后缀一致；
3. **每个订阅必须在同一宿主类型内有成对的退订**（Warning）；
4. `[GameEvent]` 标记类型的契约（struct + `IGameEvent` + 无实例方法）。

## 诊断规则（默认 Warning，可经 .editorconfig 调级）

| ID | 规则 | 说明 |
| --- | --- | --- |
| MA7000 | 禁止匿名函数订阅/退订 | `EventBus.Subscribe` / `EventBus.Unsubscribe` 的实参不得是 lambda/匿名方法——匿名委托每次生成新实例，`Unsubscribe` 的值等价匹配（同方法同目标）永不命中，订阅即泄漏 |
| MA7001 | 带参回调必须 `in` 修饰 | `OnXxxEvent` 的参数必须是 `in XxxEvent evt`（缺 `in`、或写成 `ref`/`out` 均告警）。方法组转换要求 ref-kind 精确匹配。IDE 内提供一键 CodeFix「添加 in 修饰」 |
| MA7002 | 参数类型与方法名不匹配 | `OnFooEvent` 的参数类型应是 `FooEvent`；传入其他 `IGameEvent` struct 时告警 |
| MA7003 | **订阅缺少成对退订** | 同一宿主类型（含 `partial` 分部）内，按「事件类型 + 处理器」配对 `Subscribe` / `Unsubscribe`；配不上对的 `Subscribe` 报 Warning |
| MA7004 | `[GameEvent]` 必须为 struct | Error |
| MA7005 | `[GameEvent]` 必须实现 `IGameEvent` | Error |
| MA7006 | `[GameEvent]` 不得含实例方法 | Warning |

调级示例（工程根 `.editorconfig`）：

```ini
[*.cs]
dotnet_diagnostic.MA7000.severity = error   # 匿名订阅直接挡编译
dotnet_diagnostic.MA7001.severity = warning
dotnet_diagnostic.MA7003.severity = error   # 漏退订挡编译
```

> 兼容提示：MA7004–MA7006 原与订阅规范共用 MA7001–MA7003（同 ID 两种含义），现已拆开；如曾针对 `[GameEvent]` 写过 `.editorconfig` 调级，请把对应 ID 改为 MA7004/MA7005/MA7006。

## MA7003 配对规则细节

- **配对键**：事件泛型实参（`Subscribe<TEvent>` / `Unsubscribe<TEvent>` 的 `TEvent`）+ 处理器符号（含重载参数与 `ref`/`in` kind；`this.OnFoo` 与 `other.OnFoo` 视为不同目标）。
- **配对范围**：同一个宿主类型，跨 `partial` 分部文件也算同一类型；嵌套类型各自独立。
- **多集计数**：同键下 `Subscribe` 数量多于 `Unsubscribe` 时，多出的那些 `Subscribe` 报警；报警落在订阅调用处。
- **匿名处理器**：由 MA7000 单独负责，MA7003 跳过，避免同一处重复报警。
- **检查时机**：编译期（compilation-end 分析），结果进 Unity Console；IDE 实时分析可能不展示该类诊断，以编译结果为准。
- **不计数的情况**：`EventBus.ClearAllChannels()` 之类的全局清理不会被视为成对退订——规范仍要求订阅方自己成对 `Unsubscribe`。

示例：

```csharp
public class PlayerSystem
{
    private void OnEnable()
    {
        EventBus.Subscribe<PlayerSpawnedEvent>(OnPlayerSpawnedEvent);   // 有配对 → 不告警
        EventBus.Subscribe<SceneLoadedEvent>(OnSceneLoadedEvent);       // 无配对 → MA7003
    }

    private void OnDisable()
    {
        EventBus.Unsubscribe<PlayerSpawnedEvent>(OnPlayerSpawnedEvent);
    }

    private void OnPlayerSpawnedEvent(in PlayerSpawnedEvent evt) { ... }
    private void OnSceneLoadedEvent(in SceneLoadedEvent evt) { ... }
}
```

无参回调不再有任何生成器桥接，也不要求宿主 `partial`；若要订阅无参逻辑，请自行写带 `in` 参数的包装方法：

```csharp
public class HudController
{
    private EventDelegate<SceneLoadedEvent> _onSceneLoaded;

    public HudController() => _onSceneLoaded = OnSceneLoadedEvent;

    private void OnEnable()  => EventBus.Subscribe(_onSceneLoaded);
    private void OnDisable() => EventBus.Unsubscribe(_onSceneLoaded); // 同一委托字段 → 值等价命中

    private void OnSceneLoadedEvent(in SceneLoadedEvent evt) => Refresh();
}
```

## 边界与限制

- 只识别静态类 `Moirai.Atropos.EventBus` 上的 `Subscribe` / `Unsubscribe`；其他总线/实例的同类方法不在范围内。
- 处理器无法解析为符号（如 lambda、复杂表达式）时跳过 MA7003；lambda 由 MA7000 覆盖。
- 退订写在别的类型（如公共清理辅助类）不算配对，仍会告警。
- `<auto-generated>` 文件头的代码对所有 MA 诊断豁免。
- 诊断均默认 Warning；Unity Console 不显示 IDE 级 CodeFix，MA7001 的一键修复需在 Visual Studio / Rider 中使用。

## 构建

```bash
# 源码目录内
cd Packages/com.moirai.framework/SourceGenerators/Source~/EventBusAnalyzer
dotnet build -c Release        # DLL 直出 SourceGenerators/EventBusAnalyzer.dll

# 自检（诊断计数 + 零 Source Generator 校验）
cd ../EventBusAnalyzer.Probe
dotnet run -c Release
```

版本锁定：`Microsoft.CodeAnalysis.CSharp 4.3.0`（Unity 6000 内置 Roslyn 版本），目标框架 `netstandard2.0`，与其他 `Source~/` 项目同口径。
