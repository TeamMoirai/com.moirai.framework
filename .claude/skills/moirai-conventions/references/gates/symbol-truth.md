# 符号真名口径

执行体是 `.claude/skills/moirai-conventions/scripts/check_config_surface.py` 的 C 段，登记表与排除表在同目录的
`.claude/skills/moirai-conventions/scripts/config-surface-debt.json`。量具是本地脚本，不需要开着的编辑器。
本块只述口径与修法优先级，不放第二份实现——判据形状要变时改那个脚本，本块跟着改述；只改本层就是话与牙没对上号。

## 判据口径

候选（正向）取自 markdown 正文的**行内反引号段**与 ``` **围栏代码块内的每一行**，两者走同一条过滤链；段里命中框架符号书写形态的标识符入集。

| 环节 | 规则 |
|---|---|
| 取段 | 行内反引号之间的内容整段受检：段内含 `/`，或以 `.xx`–`.xxxx` 结尾（路径、文件扩展、菜单串）时整段跳过。围栏代码块按行受检：代码行里到处是 `//` 与 `a/b`，整行按路径跳过等于把骨架代码块放出射程，所以目录段与带已知扩展名的文件名改按**词级**让位 |
| 取词 | 段内逐词切字母数字下划线；长度 < 4、首字母小写的词不收 |
| 命中 | 尾缀落在 `TYPE_SUFFIXES`（`Service`、`Handler`、`Window`、`Settings`、`Attribute`、`Event`、`Base`、`Args`、`Manager`、`System`、`Bridge`、`Lease`、`Entry`、`Slot`、`Options`、`Request`），或形如 `E???`/`I???`（第二字母大写）的枚举名与标记接口名 |
| 排除 | 排除表（登记表 `non_framework_names` 段，B 档）：Unity/BCL/Odin/NUnit/第三方的同名者。每项要带自洽的 `class`，还要带一条**限定名形状**的归属证据——以外部根命名空间起头、末段等于该名字（`System.Collections.IEnumerator`、`UnityEngine.EventSystems.EventSystem` 这种），含糊话术不算证据；根段清单与判定都由量具自己说。表里现在是哪些名字、有几项，由登记表自己说，本层不抄名单（抄进来就对不上）；受《债务登记》那几条对账约束，**牙分三级见该段** |
| 归一 | 名字本身无声明、而它加 `Attribute` 有声明时，候选归一成 `XAttribute`（C# 允许 `[Window]` 省后缀）；不靠塞排除表放过。`{TOKEN}` 模板邻接、`<Module>` 尖括号占位与示例段名同样在抽取里归一化。示例段名分两条词根档：**首段**落进 `Some`/`Any`/`Foo`/`Xxx`/`My`/`Sample`/`New`/`Old` 即丢；**任一段**落进 `Some`/`Any`/`Foo`/`Xxx` 即丢。后一条只在这些词根于本包声明名的 CamelCase 段里一名不存时才不可能吃掉真实类型名，那句保证不写在文档里，由量具的声明集自检当场断言——词根一旦命中声明段就按「量不出来」收，此时的绿不可信。前一条按首段丢，`MyColumns`、`MyCompressedSerializer`、`Sample` 这类首段命中的已声明名本来就在声明集里、进不了候选，所以不产生假绿 |
| 不收 | 成员形态的五种书写都不收：点号前是已声明类型的成员访问、紧跟 `(` 的调用、紧跟 `=` 的 `Name=`/`Name=value` 清单形态、`_ = Name;` 赋值右值裸名、`event <Type> Name;` 声明位（这条只收坐在声明位上的那个名字，中间的类型名 `EventHandler` 照旧进候选）；再加以已判定成员同一条并列串（`/`、`、`、`,` 相连）的其余书写同判成员形态——`UIService.HasWindow<T>` / `GetWindow<T>` / `GetTopWindow()` 三条是一条枚举，不是三个类型。命名空间限定（点号前无声明）**不**豁免——否则死 API 加个前缀就躲开判据 |

声明集：扫 `Runtime/` 与 `Editor/` 下全部 `.cs` 的 `class`/`struct`/`interface`/`enum` 声明名（含嵌套类型）。
量具自检 = 集合规模下限 + `ServiceBase`/`UIWindow`/`EventManager` 三条必然非零的对照；只查规模会让一个抓漏一半的正则给出看着可信的假绿。

成员名不在「类型是否存在」这一口径内——方法、字段与源生成成员一律不查，覆盖面只到类型面。
落在成员面的书写先在抽取里归一化（`_ = Name;` 赋值右值与 `event <Type> Name;` 声明位就是为此补的）；
归一化仍收不干净的（骨架里按成员取用、正文里把成员名裸写成散文用法，两种书写在同一个文件里并存）走登记表的
`symbols.member_form` 分节，模板拿示例参数代入出来的产物名走 `symbols.example_placeholder` 分节，
两节都要求量具当场复算得出分类依据，复算不出即红：`member_form` 要该命令文件真有一处把**这个名字**写成成员形态的取用点；
`example_placeholder` 要同一行的**行内反引号里**写出被代入的参数名，且词根长度不小于量具的门槛——散文里随口一提的
`Event` 不给 `EventSystem` 当依据，接口前缀 `I` 也不给 `IEvent` 当依据；围栏代码行整行受检、没有行内反引号可言，
所以它不产出示例依据（被代入的参数名是在正文里交代给读者的）。
`Handler`（`ProviderHandlerHostGenerator` 发射的活属性）与 `OnEvent`（示例自己 `public event EventHandler OnEvent;`
声明的成员）就是这么记的：它们是活的框架成员，记进 `dead_api` 会让清债的正确动作变成把写对的文档改错。

## 射程边界

**文件射程**：执行体的候选集只从 `.claude/commands` 目录下递归取的 `.md`。`CLAUDE.md`、本层四块与其它 skill 都不在正向扫描之内
——本层里写错的符号没有守卫替你报错，只有读的人会发现，落笔前自己读到声明处。

**段射程**：正向抽取同时覆盖行内反引号段与 ``` 围栏代码块里的每一行，两者走同一条过滤链——往骨架代码块里塞一个本包无声明的类型名会打红。
剩下的边界在段级与口径级：行内段含 `/` 或以文件扩展收尾时整段不受检，围栏里的目录段与文件名按词不受检；
成员名不在「类型是否存在」这一口径内（见《判据口径》末段）。

**口径射程（本层最容易低估的一条）**：这一段只判「这个名字在本包有没有声明」，**不判形状**。下面这些照做会编译不过、或编译过了行为不对，而本段全盲：

- 形参的**个数、类型、顺序、有没有默认值**——特性按位置走位尤其危险（本包有过 `UIWindowCodegen` 因此静默串档的先例）；已删除的参数被当成现存 API 写进示例也一样查不出来。
- **委托形制**（处理器签名与注册入口的委托是否同参）、方法组能否绑定。
- 覆写点的**访问修饰符与 `abstract`/`virtual`**：`public abstract` 的成员被写成 `protected override`、或对 abstract 调 `base.X()`，类型名全都存在。
- 类型**能不能被实例化/挂载**：`abstract` 基类存在，但「挂到 GameObject 上」这句话依然错。
- 同名跨档：同一个成员名在服务档没有、在 UI 档有（`OnDestroy` 这类），按名字判存在会给出错误的安全感。
- 文档里的**语义注释与路径/行号**：一行 `//` 是不是真的、指向的目录与文件在不在盘上，本段一概不看。

所以「C 段绿」只等于「没有拼错到查无此名的类型」，不等于「这份示例能编译」，更不等于「这份示例描述的行为是对的」。
命令正文的骨架要以**同包既有的真实实现**逐字对照（找一个已落地的同类件，比对它的声明点与形参表），别以本段的绿为准。
两处「扩展名」的口径是**故意分叉**的：行内那条用通用形状 `\.\w{2,4}$`，围栏那条用一份已知扩展名清单——
按形状收会把 `Resources.Load` 这类成员当文件名放行，所以围栏里改核清单；代价是清单外的扩展名
（`.csproj`、`.mat`、`.controller` 一类）在围栏里不被认作文件名，会当成标识符进候选。分叉的方向是响的：
多报而不漏报，红因看得见，靠登记或改命令正文收掉，不放任何真死 API 出门。

## 债务登记

登记表的 `symbols` 段按三档分节：`dead_api`（A 档，本包查无声明的死写法）、`member_form` 与
`example_placeholder`（C 档，口径外的书写分类）。三节的键都是 `<命令文件名>|<符号>`（与所在目录无关，
命令搬进档位子目录后仍有效），值是 `class` 与理由；`class` 由量具校验，必须与所在节的档位自洽——
不校验的档位标签就是纯装饰，串档没人报。

`dead_api` 是债务，走单向棘轮：每项必须仍命中，修好一条删一条，只准降不准升；新增登记单列清理任务，
不夹带在别的改动同一提交里。`member_form`/`example_placeholder` 不进债务豁免计数也不走这条棘轮，
读数单列「口径外候选 N 条」，但同样不许烂在那里：不再命中候选集即红，且量具必须当场复算得出它的分类依据。

反向探针与正向**同量法**：登记项只在该符号仍被同一套抽取从该命令文件取到候选时才成立。名字从候选集里消失（正文删掉它、
或退成不受检的段级形态）时登记项当场上红——一句「框架里没有 `X`」的否定话撑不住一条登记。

排除表（B 档，非框架同名者）另受两条反向对账，量的都是**候选集**而不是形态命中集（形态命中集在四道筛之前，
拿它当证据就等于往排除表塞任何只以成员形态出现的名字都白拿一条豁免）：名字在本包确有声明即为陈旧豁免、该删；
今天挡不到任何候选也该删。再加一条矛盾对账：同一个名字既坐在 `symbols` 的符号位又在排除表即红。

**排除表的牙分三级，别把这一段读成「进了排除表就有人替你把关」**：

1. 「两边挂着」有牙。同名同时出现在 `symbols` 的符号位与排除表，当场红——它挡的是「改了档但原登记没删净」这一种。
2. `belongs` 的**形状**有牙。它必须写得出一个以外部根命名空间起头、末段等于该名字的限定名
   （根段清单与判定见量具的 `EXTERNAL_ROOTS` 与 `belongs_qualifies`）；「Unity 的 UI 组件」这类含糊话按
   「量不出来」收（退出码 2），不是按合格收。这一条**只挡含糊话**。
3. 「删净 `dead_api` 原登记、只留一条写了诚实限定名的排除表项」**无牙**。`UnityEngine.EventSystems.EventSystem`
   这种形状过关、读着也成立的限定名照样 `exit 0`：判 A 还是判 B 的分界是「命令在此断言的是不是本包的 API」，
   限定名形状读不出来。要抓它得核被断言的成员——真名之后那个成员在本包有没有声明——属成员级判据，
   不在本口径内，已单列为任务。所以改档这一半靠人的纪律与 diff 里的痕迹，不靠量具；
   别把它记成「有判据兜着」而放心地把死写法搬进排除表。

## 修法优先级

1. 改命令正文用本包真名：先读被调方的实现体与声明处，再落笔，不凭记忆写签名。
2. 暂时留着的旧写法，登记进登记表并写清理由，同时单列一轮清理。
3. 禁止用「缩小 `TYPE_SUFFIXES`、往排除表加名字、把包根往上跳一层」让判据闭眼——那三条都能把红变成绿，且都不改变命令里的死 API。

## 复现

本地脚本一趟跑完配置层的全部判据段，不需要开着的编辑器，也不走测试桥：

```bash
python .claude/skills/moirai-conventions/scripts/check_config_surface.py
echo "exit=$?"
```

| 退出码 | 含义 |
|---|---|
| 0 | 各判据段全部真跑过且无违例 |
| 1 | 跑过了，`VIOLATION` 行逐条点名未归因违例 |
| 2 | 量不出来：`MEASURE-FAIL` 行给原因（目录取不到、登记表读不动、声明集自检不过）——绝不等于合格 |

判据段的分段标签、段数与每段标题都由量具当场打出，本层不复述清单也不写死计数——加一段判据时抄进来的名单必然漂。
需要开着的编辑器的其它判据仍走 `.claude/skills/moirai-conventions/references/gates/bridge-protocol.md` 的桥形状。

A/B 证伪（没做过证伪就不许声称判据能判假）：往任一命令文件的围栏代码块里加一行只含 `EventSystem` 的语句，
重跑必须打红并点名该文件；验完删净探针行，再跑一次确认回到退出码 0，并核 `git diff --numstat` 对该文件为空。
