# 提交、文档与发版细则（本包）

## 版本号归属

本包没有发版工作流；`package.json` 版本 1.0.0 由发布动作维护，日常提交不碰 `version`。

## 文档同步

| 文档 | 何时改 |
|---|---|
| `README.md` | 安装步骤、菜单、环境要求变化时 |
| `AGENTS.md` 与 `.agent/` | 规范变化时只改权威层 |

## 提交纪律

- 中文 conventional commits：`type(scope): 一句净结果`。
- 只写现行事实与净结果；不写重构过程、不写参考工程名。
- 按显式路径暂存；共享工作树可能有别人的未提交改动，禁止 `git add -A` / `git add .`。
- 提交后 `git show --name-only` 复核暂存集。
- 中大型功能/重构先建分支；提交粒度按功能步，不按文件。
- 新增 `.cs` 不要手写 `.meta`：让 Unity 生成，随源文件同笔提交。

## 发版预检（本地）

1. `git status --short`：工作树归属清楚；别人的未提交改动不混入。
2. `package.json` 的 `version` 与当前已发布 tag 一致（未被手工改动）。
3. 用户可见变化已同步 README/文档；README 的安装步骤与脚本一致。
4. 新增/移动的源文件与 `.meta` 成对。
5. 编译门 0 error；测试证据或"无测试装配"事实已写明。
6. 没有把"CI 跑过测试""覆盖率达标""CHANGELOG 已更新"写成事实（除非本包确实有对应工作流/文件）。

## 不得写进提交或文档的句子

- "CI 已跑测试 / 覆盖率已达标"：本包没有 CI 工作流，不跑测试、不产生覆盖率。
- 本包没有 CHANGELOG 文件；版本以 `package.json` 为准。
- "已通过 PlayMode 回归"：本包无测试装配
- 参考工程名、其他包的内部规范名、过程性计划文档路径。
